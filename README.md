# PyGNN-JCGS

PyTorch feed-forward **generative moment matching networks (GMMNs)** and their
adaptive-bandwidth extension (**AGMMNs**) for learning multivariate distributions,
especially copulas. A generator maps a simple latent prior to observations and
learns by minimizing a discrepancy between generated and observed samples.

The package provides fixed-bandwidth and adaptive training, pseudo-random and
quasi-random sampling, model persistence, and self-contained tutorials with
synthetic copula data.

The associated research article is:

Marius Hofert and Gan Yao (2026). **Adaptive Generative Moment Matching Networks
for Improved Learning of Dependence Structures.** *Journal of Computational and
Graphical Statistics*, 1–15.
[https://doi.org/10.1080/10618600.2026.2689663](https://doi.org/10.1080/10618600.2026.2689663).

The examples demonstrate the API with small datasets and short training runs.
They do not reproduce the paper's experiments or establish convergence.

## Installation

Requires Python **3.10+**, PyTorch **2.1+**, NumPy **1.24+**, SciPy **1.10+**,
and tqdm **4.65+**. Matplotlib is optional and used only when examples are run
with `--plot`.

From the repository root:

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -e .
# Optional plotting support:
python -m pip install -e '.[examples]'
```

On Windows, activate with `.venv\Scripts\activate` instead. If an accelerator
build of PyTorch is needed, install the appropriate build for the machine before
installing this package. All examples default to CPU. Select another available
device with `--device cuda` or `--device mps`.

The distribution name is `pygnn-jcgs`; Python imports use `PyGNN`. Run tutorial
commands from the checkout root: the `examples` directory is distributed as
repository source, rather than installed as a separate Python package.

## Quick start

This complete example generates training data locally, trains a fixed-bandwidth
GMMN, and draws a reproducible sample:

```python
import numpy as np
import torch
from PyGNN import FNN, fit, pobs, save_model

torch.manual_seed(42)
rng = np.random.default_rng(42)
observations = rng.multivariate_normal(
    mean=[0, 0], cov=[[1, 0.7], [0.7, 1]], size=512
)
training = torch.tensor(pobs(observations), dtype=torch.float32)

model = FNN(
    dims=[2, 64, 2],
    activations=["ReLU", "Sigmoid"],
    input_dist="N",
    loss_fun="MMD",
    MMD_normalized=True,
    device="cpu",
)
losses = fit(
    model, training, batch_size=128, nEpochs=40,
    adaBW=False, verbose=0,
)

model.eval()
with torch.no_grad():
    samples = model.sample(256, seed=123)
save_model(model, "outputs/model.pt")
```

`fit` updates the model in place and returns one Python float per completed
epoch. With `adaBW=False`, the default kernel uses six fixed bandwidths.
The general `fit` API defaults to `adaBW=True`; this example explicitly selects
the simpler fixed-bandwidth mode.

| --- | --- | --- |
| `gaussian_copula` | Correlated Gaussian data, pseudo-observations, fixed MMD training | `outputs/gaussian/` |
| `gaussian_copula --absolute` | The absolute-Gaussian transformation used in the basic scripts | Use `--output` to choose a separate folder |
| `clayton_copula` | Positive Clayton dependence generated by a gamma frailty mixture | `outputs/clayton/` |

The training examples save `model.pt`, `training.csv`, `generated_prs.csv`,
`generated_qrs.csv`, `history.csv`, and `metrics.json`. The adaptive example also
saves `training_log.json`, the best smoothed-training checkpoint, and any
completed validation-monitoring windows. Output files use the requested folder;
reusing a folder can overwrite earlier files.

Useful options shared by the three training examples:

```bash
python -m examples.gaussian_copula --epochs 5 --ntrain 128 --ntest 64 --batch-size 32
python -m examples.clayton_copula --dim 10 --latent-dim 3 --hidden 128 --prior t
python -m examples.adaptive_copula --epochs 100 --ref-size 128 --ref-rep 3 \

```

The examples set PyTorch's CPU thread count to one for small problems; override
with `--threads`. Their `--seed` controls initialization, training, synthetic data,
and evaluation inputs. Exact results can vary with device and library versions.
The reported test MMD uses independently generated test data and a fixed
validation kernel. It includes the untrained score for comparison.

## Preparing data

Supply a floating tensor of shape `(number_of_observations, output_dimension)`.
For a copula, transform each marginal to pseudo-observations:

```python
import numpy as np
import torch
from PyGNN import pobs

raw = np.loadtxt("observations.csv", delimiter=",", ndmin=2)
training = torch.tensor(pobs(raw), dtype=torch.float32)
```

`pobs` returns columnwise average ranks divided by the observed count plus one.
It handles ties and keeps observed values strictly inside `(0, 1)`. NaNs remain
missing and are omitted from each column's denominator. It also accepts a vector.
For general distributions, use data on its original or suitably scaled domain
and choose a suitable output activation; a Sigmoid output is for bounded data.

Fixed-bandwidth MMD/tMMD can compare samples with NaNs by omitting coordinates
that are missing in either member of a pair. Pairs without any jointly observed
coordinates receive kernel value one. Bandwidth quantile estimation requires
complete finite data: use `adaBW=False` and explicit widths for missing data.
Infinite inputs are rejected.

## Building a network

```python
from PyGNN import FNN

model = FNN(
    [3, 128, 64, 10], ["ReLU", "LeakyReLU", "Sigmoid"],
    input_dist="N", batch_norm=False, drop_out=0.1,
    loss_fun="MMD", MMD_normalized=True, lrate=1e-3, device="cpu",
)
```

Here the prior is three-dimensional and the generated data are ten-dimensional.
Input and output dimensions need not agree.

| Argument | Default | Meaning |
| --- | --- | --- |
| `dims` | Required | Input, hidden, and output widths; positive integers |
| `activations` | Required | Exactly one entry per stage; use `None` for no activation |
| `input_dist` | `"N"` | `N`: independent standard normals; `U`: independent uniforms; `t`: multivariate t4; `P`: explicit prior |
| `batch_norm` | `False` | Batch normalization after each affine stage, including output, before activation |
| `drop_out` | `0` | Dropout on hidden stages; probability in `[0, 1)` |
| `loss_fun` | `"MMD"` | Select the loss described below |
| `MMD_normalized` | `False` | Divide squared pairwise distances by the jointly observed coordinate count |
| `lrate` | `1e-3` | Initial Adam learning rate |
| `device` | `"cpu"` | PyTorch device |

Supported activations are `ReLU`, `LeakyReLU` (PyTorch's default negative slope),
`Sigmoid`, `Tanhshrink`, `NormalQuantile`, and `None`.
`NormalQuantile` maps probabilities to standard normal quantiles; its inputs must
be strictly between zero and one. The module can also be applied directly to
probability tensors outside a network. All entries in `dims` must be positive
integer widths.

The network is an ordinary `torch.nn.Module`: call `model(x)` for a differentiable
forward pass. `model.optimizer` is Adam; `model.lossFun` is the selected loss.
`model.step(x, y, bandwidth=..., weight=...)` performs one training update and
returns a detached scalar tensor. `model.device` follows subsequent `model.to()`
calls. As with ordinary PyTorch optimizers, move the model before training;
moving an already-populated optimizer state requires separate handling.

## Losses and kernel conventions

```python
from PyGNN import LossFun

criterion = LossFun("MMD", normalized=True)
score = criterion(generated, observed, bandwidth=[0.1, 0.3, 0.7])
```

For component bandwidths `h`, the mixture kernel is
`mean_h exp(-squared_distance / (2*h*h))`. Explicit `weight` values replace the
average with a weighted sum; they are nonnegative and are used without automatic
renormalization. Bandwidths must be strictly positive and finite.

The default bandwidths are `10**[-1.5, -1, -0.5, -0.25, -0.125, -0.0625]`.
With `normalized=True`, distances are divided by the observed dimension count;
choose bandwidths with that distance scale in mind.

| Loss | Definition and intended use |
| --- | --- |
| `MMD` | `mean(Kxx) + mean(Kyy) - 2*mean(Kxy)`; biased empirical **squared** MMD including diagonals; supports unequal sample sizes |
| `tMMD` | A variance-standardized statistic; equal sample sizes of at least four; errors on nonpositive/nonfinite estimated variance |
| `CvM` | Two-sample Cramer–von Mises statistic on the unit cube; requires finite data in `[0, 1]` |
| `MSE` | Mean squared error for paired observations |
| `BCE` | Binary cross entropy for paired probabilities in `[0, 1]` |

The tMMD numerator omits within-sample diagonals but still divides their sums by
`n**2`. It is a separate statistic from the biased MMD returned by `MMD`.
Tiny negative MMD values can arise from floating-point roundoff.

MSE and BCE are pointwise objectives and require meaningful input/target pairing.
Use `adaBW=False` for them. Distribution losses instead compare two sample sets.
The distributional kernel is a Gaussian mixture. Use `PyGNN.kernels.rbf_kernel`
to evaluate its matrix directly.

## Training manual

### Fixed bandwidths

```python
losses = fit(
    model, training, nEpochs=100, batch_size=256,
    adaBW=False, bandwidth=[0.05, 0.15, 0.4], weight=[0.2, 0.4, 0.4],
    verbose=2,
)
```

Each epoch uses fresh built-in prior samples. Every training row is included,
including a short final batch. A final batch too small for batch normalization or
tMMD is merged into the preceding batch. Epoch losses are weighted by the number
of observations in each batch. `batch_size=None` means full-batch training;
`batch_size` larger than the dataset also gives one complete batch.

### Adaptive bandwidths

```python
losses = fit(
    model, training, nEpochs=200, batch_size=128, adaBW=True,
    bw_lengths=(6, 12, 24), EXQ=False,
    ref_size=256, ref_rep=5,
    val_size=256, val_rep=5, val_seed=42,
    patience=3, delta_tr=0.01, delta_val=0.001,
    chkpt_path="outputs/best_training_state.pt",
    val_hist_dir="outputs/validation",
    log_path="outputs/training_log.json",
    collect_val_every_epoch=True,
)
```

Adaptive training proceeds as follows:

1. Estimate bandwidths from quantiles of pairwise Euclidean distances in random
   subsamples. Average the estimates over `ref_rep` replicates and divide by
   `sqrt(2 * output_dimension)`. Zero estimates are floored at dtype epsilon.
2. Track the bias-corrected exponential moving average of training loss with
   smoothing weight 0.25. After `patience` epochs without the required relative
   improvement, move to the next bandwidth phase.
3. After each update, set patience to `floor(exp(1 + min(3, epoch/33)))`, where
   `epoch` is zero-based, and suspend training-plateau checks for five epochs.
4. Monitor normalized MMD with a **fixed validation kernel**. The first score is
   the window baseline. A relative improvement greater than `delta_val` ends
   monitoring successfully; no such improvement within the window requests a stop.
5. Stop on validation failure or an exhausted bandwidth schedule. With
   `force_nonstop=True`, retain the last widths and continue to `nEpochs`.

In ordinary mode, a phase with length `L` uses
`0.95 * 2**(-linspace(0, 9, L))` as distance-quantile levels.
`EXQ=True` appends three levels (0.99, 0.999, 1), so the actual kernel count is
`L+3`. `ExtendBW=True` instead estimates `L//2` quantiles and adds linear
extensions toward 0.01 and 0.99 without sorting the middle vector.
Use even lengths if requesting exactly L widths in this mode.

For more than 6,000 training rows, adaptive mode enables normalized training
distances, and for more than 8,000 rows it disables EXQ. Below those thresholds,
the model's normalization
setting and the requested EXQ flag are used. Adaptive bandwidth estimates always
use the `sqrt(2*d)` scale; setting `MMD_normalized=True` makes this convention
explicit for smaller copula datasets too.

### Parameter reference

| Parameter | Default | Purpose |
| --- | --- | --- |
| `batch_size` | `None` | Full dataset unless specified |
| `nEpochs` | `100` | Positive maximum epoch count |
| `prior` | `None` | Explicit `(N, input_dim)` tensor for `input_dist="P"` |
| `bandwidth`, `weight` | `None` | Fixed kernel settings; leave unset in adaptive mode |
| `adaBW` | `True` | Enable adaptive MMD/tMMD training |
| `ref_size`, `ref_rep` | `5000`, `100` | Bandwidth subsample size and repetitions |
| `val_size`, `val_rep` | `3000`, `50` | Validation subsample size and repetitions |
| `val_bw` | `None` | Fixed validation widths; None uses the six default widths |
| `val_seed` | `42` | Local validation seed reused each evaluation |
| `delta_tr`, `delta_val` | `0.0`, `0.0` | Required relative decreases, each in `[0, 1)` |
| `patience` | `3` | Initial plateau window, adjusted after updates |
| `bw_lengths` | `(6, 12, 24)` | Successive quantile counts; caller's sequence is never mutated |
| `adaptive_lr` | `False` | Divide Adam learning rate by five on each of the first two bandwidth updates |
| `EXQ`, `ExtendBW` | `True`, `False` | Optional quantile/extension conventions described above |
| `force_nonstop` | `False` | Continue after a recorded stop request, with adaptation disabled |
| `collect_val_every_epoch` | `False` | Record validation every epoch without changing the stopping rule |

The general API's reference and validation defaults are research-scale and can
be expensive. The runnable examples deliberately override them. Subsample sizes
are capped at the available sample size. Pairwise losses require quadratic work
in batch size; reducing `batch_size`, `ref_size`, and `val_size` is the first way
to reduce memory use. More kernel components and repetitions increase runtime.

### Logs and checkpoints

| Parameter | Default | Output behavior |
| --- | --- | --- |
| `verbose` | `2` | 0: silent; 1: progress bar; 2: bar and ten-epoch reports; 3: each epoch |
| `chkpt_path` | `"checkpoint.pt"` | Save state dict on smoothed-training improvement in adaptive mode; None disables |
| `val_hist_dir` | `"."` | Directory for validation-window CSVs; None disables |
| `log_path` | `"train_log.json"` | JSON log for adaptive mode or per-epoch validation; None disables |
| `take_snapshot` | `None` | Iterable of one-based epochs, such as `[10, 25, 50]` |
| `snapshot_dir` | `"./snapshots"` | Parent directory for `E10.pt`, etc.; created automatically |

Logs contain `update`, `stop`, `bandwidths`, `stop_reason`, `epochs_completed`,
and `forced_continuation`, plus `val_losses` when requested. `update` and `stop`
use **zero-based** epoch indices. Snapshots and progress messages use **one-based**
epochs. Stops are logged even when `force_nonstop=True` continues training.

The same log remains available as `model.training_log_`; final training widths
are in `model.bandwidth_`. These attributes are fitting results and are not part
of the model state dict or inference artifact.

Checkpoints record improvements of smoothed **training** loss, whose kernel can
change between phases. They are not selected by a globally comparable validation
score. `fit` keeps final weights and does not automatically restore a checkpoint.

## Sampling and validation

```python
model.eval()
with torch.no_grad():
    pseudo_random = model.sample(1024, seed=123)
    quasi_random = model.sample(1024, QRS=True, seed=123)
    generator = torch.Generator().manual_seed(123)
    another_sample = model.sample(1024, generator=generator)
```

All built-in priors support pseudo-random sampling and scrambled Sobol' sampling.
Use power-of-two QRS sizes to preserve Sobol' balance properties; see the
[SciPy Sobol documentation](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.qmc.Sobol.html).
For `t`, each row shares a chi-square scale, giving a multivariate t4 with identity
scale and covariance `2I`. The pure Python QRS implementation uses d normal
coordinates and one chi-square coordinate to form the multivariate t mixture.

`seed` controls the scramble for QRS and a local generator for PRS. Supply either
`seed` or `generator`; a torch generator is used only for PRS. A generator on CPU
can produce inputs subsequently moved to an accelerator.

`sample()` preserves autograd and the model's current train/eval mode. Use
`eval()` and `no_grad()` for inference, especially with dropout or batch
normalization. A Sigmoid confines outputs to the unit interval but does not
guarantee exactly uniform margins. To obtain empirical uniform margins, apply
`pobs(generated.cpu().numpy())`, or use `sample_saved_model --rank`.

For custom prior `P`, provide prior samples to `fit` and call `model(prior)`
directly for inference. `sample()` cannot draw an unspecified prior.

```python
from PyGNN import AvgMMD

validation_score = AvgMMD(model, training, val_size=256, B=5, seed=42)
```

`AvgMMD` always uses normalized squared MMD. It draws target subsamples without
replacement and fresh model samples, averages B replicates, temporarily switches
to evaluation mode, and restores all modes and buffers without consuming the
training RNG stream. Pass `prior=...` for a custom prior. A separate held-out
tensor may be supplied as `data` when an external validation/test score is wanted.
The internal adaptive stopping diagnostic uses the training sample and should
not be described as held-out validation.

## Saving and loading

For portable inference, save both architecture and weights:

```python
import torch
from PyGNN import save_model, load_model

save_model(model, "outputs/model.pt")
restored = load_model("outputs/model.pt", device="cpu")  # already in eval mode
with torch.no_grad():
    samples = restored.sample(256, seed=123)
```

`save_model` stores constructor settings, parameter dtype, and weights.
`load_model` uses `torch.load(..., weights_only=True)` and moves the model to the
requested device. These inference artifacts do not include Adam state, the
adaptive controller, random states, or training logs, so they do not resume
training exactly where it left off.

Adaptive checkpoints and snapshots contain plain PyTorch state dicts.
Recreate the matching architecture explicitly to read them:

```python
restored = FNN([2, 64, 2], ["ReLU", "Sigmoid"], device="cpu")
weights = torch.load("outputs/best_training_state.pt", map_location="cpu", weights_only=True)
restored.load_state_dict(weights)
restored.eval()
```

Use the architecture, activation choices, and normalization settings from the
training run. A plain state dict cannot be passed to `load_model`, which
expects the metadata-bearing `save_model` format.

## Repository structure and development

```text
PyGNN/
  models.py          Network construction, forward pass, sampling interface
  sampling.py        Built-in priors and scrambled Sobol' transformations
  preprocessing.py   Rank-based pseudo-observations
  kernels.py         Gaussian mixture kernel and missing-coordinate distances
  losses.py          MMD, tMMD, CvM, MSE, BCE
  bandwidths.py      Distance-quantile estimates and bandwidth schedules
  early_stopping.py  Smoothing, plateau detection, validation windows
  validation.py      Reproducible normalized MMD diagnostics
  training.py        Mini-batches and adaptive phase coordination
  persistence.py     Inference artifacts and JSON logs
examples/            Synthetic datasets, tutorials, saved-model sampling
tests/               Loss definitions, gradients, sampling, and training tests
```

The primary public API is available from the package:

```python
from PyGNN import FNN, LossFun, fit, AvgMMD, pobs, save_model, load_model
```

Specialized helpers are available from their corresponding modules:

```python
from PyGNN.bandwidths import quantile_estimate, qvec_by_length, extend_bw
from PyGNN.sampling import drawStdNormal, drawStdUniform, drawStdT4
```

Run the regression suite using the installed runtime dependencies; no separate
test framework is required:

```bash
python -m unittest discover -s tests -v
```

The suite checks independent scalar definitions of the losses, kernel gradients,
missingness, seeded PRS/QRS, validation state preservation, adaptive transitions,
remainder batches, custom priors, public imports, and artifact round trips.
See [VALIDATION.md](VALIDATION.md) for the environment and example runs checked
when preparing this repository.
